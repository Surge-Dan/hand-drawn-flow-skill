# 工具适配

核心设计方法不依赖特定服务。实际生成遵循当前宿主公开的工具契约；下列适配是使用说明，不是跨平台可用性承诺。

## 能力路由

- 有原生图像生成能力：优先使用它，不另行索要 API Key。
- 用户明确指定已可用的工具：按用户要求执行。
- 没有图像生成能力：交付内容与提示词，明确图片未完成。不得用 HTML/SVG 截图代替用户要的生成式手绘图片。
- 有生成能力但无图像查看能力：可以生成，不能声称完成视觉核对。

本 Skill 不自动安装依赖、购买服务、登录账号或发布图片。

## 批量执行与连接失败

默认逐张调用，不并发压入一批昂贵生图请求。每张返回后立即展示、记录真实路径并保存项目所需文件，再开始下一张。保留已完成结果，不因其他图片失败而重新生成整批。

任务状态区分：待提交、生成中、已生成待核对、已交付、调用失败。以工具返回为准；长时间未返回不等于失败，不提交重复请求。需要等待时按宿主工具规则等待，并向用户说明真实进度。

- **发送／连接错误，未返回图片**：保留原提示词和错误信息。首个请求失败时暂停后续提交，可用同一请求串行重试一次；若此前整批已经失败，选一张代表请求做恢复验证，不重试整个批次。
- **失败原因不清楚且有成功历史**：可用此前成功的最小相关请求做一次对照。成功只证明此时该请求可运行，不能声称确定了网络根因或彻底修复服务。
- **仍失败**：停止自动重试，说明已检查的层级和未生成项。只有运行时存在已授权替代工具时才使用；涉及另一个服务、API Key或付费路径时按宿主要求先确认，不擅自切换。
- **返回图片但内容错误**：进入质量检查与修正，不能按连接失败处理。

连接恢复测试与画面修正各有独立目的和有界次数，不混为无限循环。恢复后继续未完成图片，不把提示词或旧图称作新样图。

不要将“error sending request”自行具体归因为用户代理、网络配置、并发限流或某个模型。没有进一步证据时，仅确认调用报告的失败阶段。设计 Skill 能改进调用与恢复流程，但无法修改远端生成服务内部。

## 当前 Codex 内置工具适配

在可用时使用 `image_gen.imagegen` 对应的内置生成工具；参数以运行时 schema 为准。

- 全新无参考图：传入提示词，不带参考参数。
- 所有参考图片都有本地路径：使用 `referenced_image_paths`。
- 至少一张目标图仅在对话里：使用覆盖所需图片的最小 `num_last_images_to_include`，不超过工具上限。
- 两种参考机制不要同时使用。无法覆盖全部必需图片时，请用户重新附上缺失图片。
- 本地待编辑图必须先查看。编辑需要保留的内容在提示词中列清楚。
- 纸面图解默认非透明背景；用户要求透明或原图有透明且需保留时按工具规则处理。
- 比例写进提示词；若工具提供原生尺寸参数可使用，但不要虚构不存在的参数。

当前内置工具没有通用输出路径参数。生成后读取工具返回的实际文件信息；项目需要图片时复制选定结果到任务目录，保留原文件。不凭猜测填写图片路径。

## 尺寸和文件

读取实际文件尺寸，核对宽高关系。3:4 用4×宽=3×高检查；16:9 用9×宽=16×高；1:1 用宽=高。工具只给显示结果、无法读元数据时，说明比例未作像素级核验。

不擅自裁切、拉伸、补边或程序覆盖文字来制造合格结果；需要改图时使用宿主允许的图像编辑能力。用户另有明确加工要求时遵从。

记录工具真实产出的格式和路径。不把 `.jpg` 改名为 `.png` 当作转换。提示词记录服务于复现设计决策，不承诺再次调用得到像素相同结果。
