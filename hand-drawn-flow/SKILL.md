# 手绘流程图

把内容讲明白，再让笔触有性格。读者应看出对象是什么、发生了什么变化、关系为什么成立。默认交付实际图片，不用一段提示词冒充成品。

优先级：事实与关系 → 阅读清楚 → 主题适配 → 手绘质感 → 视觉新意。丰富与克制都可以成立；密度由内容决定，不用纸纹或空白假装设计。

辨识度来自讲解方法：**主线回答问题，对象呈现变化，难点获得空间**。这不是必须凑齐的三个装饰模块；比较、分类等任务可不跟踪对象。以同一关系稿约束风格、比例和编辑，避免换画风就改变含义。

## 1. 确认任务，不重复访谈

先从现有请求提取：读者、核心问题、输入角色、用途、比例、风格和输出模式。只询问会改变解释范围或事实含义的缺口。用户已要求制作且材料充分时，简述选择后执行，不额外设置审批环节。

默认：中文、3:4、单张、统一手绘流程图风格。插图设置为无插图或少量辅助插图；未指定时仅在有助解释对象时加入少量小图。按内容选择顺序主线、角色泳道、条件分支或机制展开，不把画法差异包装成多个风格，也不每次发设置问卷。

需求模糊、材料冲突或复杂约束时读 [引导与边界](references/intake-and-boundaries.md)。每轮只问一个影响结果的关键问题，提供有区别的选项和建议；不询问材料中已有答案。明确需求直接执行。用户要求“任何主题”不意味着接受与知识图解无关的制作任务，也不意味着承诺零错误。

| 请求 | 路径 |
| --- | --- |
| 完整材料转图 | 整理材料，建立关系，直接设计 |
| 上传文件／文字与文件混合 | 先按文件接入规则读取，建立覆盖与来源记录，再解构内容；不能把附件文件名当成已读取正文 |
| 仅给主题 | 明确核心问题；必要时核实知识；关键范围有歧义才问 |
| 参考图＋新内容 | 看图后区分内容来源、风格参考、改绘对象、补充素材 |
| 修改现有图 | 列出修改项与保留项，只改相关内容；成品仍需检查漂移 |
| 仅分析／仅提示词 | 完成相应中间产物即停止，不生成图片 |
| 要可编辑图 | 说明本 Skill 输出位图，按用户所需交付转交合适能力，不假装可编辑 |

检查本次宿主是否具备看图和生图能力。缺少生图能力时给出内容骨架与完整绘图指令，明确图片未完成，不安装工具或切换付费服务。

## 2. 读取并解构材料

出现附件、文件路径或多份资料时，先读 [文件接入](references/file-intake.md)。区分内容来源、视觉参考和编辑对象；记录成功读取、未读取、解析不确定范围，以及关键内容的实际位置。长文件先建内容地图，再深入用户范围；不能以目录或开头片段代替读完全文。

读 [材料到流程图](references/content-to-visual.md)，提取步骤、机制或关系，建立精简内容底稿。没有执行过程时选择层级、比较或关系结构，不编造顺序；故事卡整理为事件流程、时间线或人物关系，不自动转绘本。明确只做某章时无需询问是否概括全书。

## 3. 锁定内容与关系

建立简短内部底稿：必须出现的内容、允许压缩的解释、事实出处、示例标识、未解决疑点。数字、单位、公式、专名与条件逐项保留。资料冲突、仅主题、专业知识或需要补充事实时读 [内容与可信度](references/content-and-trust.md)。

将内容转成关系稿；按 [图解语法](references/diagram-grammar.md) 选择顺序、条件、并行、循环、包含、比较或注释。给关键节点和连接临时编号，供核对使用，编号不进入成品，除非它本身是读者需要的步骤序号。

为本图保留最小验收依据：必须出现的文字、关键连接及条件、不得改变的事实与视觉约束。简单图可用几行；复杂图按节点与连接列表记录。用户修改时先更新底稿，再改图。

同一份图里区分“下一步”“数据流向”“解释引线”；不能因为要画流程图就虚构因果、顺序或循环。

## 4. 决定怎么讲

选一个主结构，必要时加一种局部辅助结构。问自己：读者最容易卡在哪里？把最大的解释空间给这个位置，简单步骤保持短。

复杂内容内部比较两个简短构图方案，选择解释能力更强且阅读负担更低的一种；通常只渲染一种。简单明确任务直接选型，不机械增加步骤。

适合时用一个具体对象贯穿过程，显示每步输入和输出的变化。对象的名称、颜色和画法跨步骤一致。分类、对比等不适合故事的内容，不强行添加角色与情节。

每个可视元素必须有用途：表达对象、变化、条件、数量、分组或提醒。删除无用途的图标和重复边框。图形能解释的关系，不再叠一段同义长文字。

按 [布局与比例](references/layout-and-ratios.md) 编排实际画面。换比例需要重排，不能裁切或拉伸。装不下时优先压缩重复解释；仍过密则提出拆分，用户未允许时不擅自从一张变成组图。

多角色、多个条件回路、长文、公式或强制单张时读 [复杂度与版面](references/complexity-and-composition.md)。先解决语义，再分配区域、对象和连线路径，最后选择视觉语言。不可用缩小全部文字或删除异常分支换取简洁。

## 5. 选择手绘语言

读 [统一风格与插图设置](references/styles.md)，保持清晰手写感、功能色、准确连接和邻近旁注。按 [布局与比例](references/layout-and-ratios.md) 的内容路由选择构图；同一风格不等于相同坐标或纵向编号模板。插图仅解释节点。用户参考传达视觉语言，不自动锁定参考图布局；明确要求复用布局时才照其组织。

确定具体的笔触、字形、颜色角色、分组方式、强调方式和密度。保持统一，但不把所有主题画成相同方框。

按 [视觉标准](references/visual-system.md) 落实字体层级、颜色职责、组内组间距、边缘安全区和背景强度。高级感来自层级与节制，不通过大标题、做旧纸和装饰符号制造。输出布局意图即可，不声称文字提示能保证精确像素。

使用参考图的视觉关系，排除仅属于该样本的作者署名、内容、品牌和布局。原图含有多少步骤，不是新图应该有多少步骤的依据。

## 6. 生成实际图片

按 [绘图指令](references/prompt-compiler.md) 把底稿、关系与设计编成可执行要求。用明确文本和具体画面关系，避免堆砌“高级、精致、有设计感”。

生成或编辑时读 [工具适配](references/rendering.md)，使用宿主实际可用的图像能力。需要参考图片时传入实际图片，并标明角色。只分析图片不代表已经将它提供给生成工具。

多张任务默认逐张生成，每张完成就展示、保存并记录状态，不等整批全部结束。发送或连接失败按工具适配里的恢复流程处理；不要把连接错误误判为提示词无效，或把未生成的图片算作已交付。

复杂任务可先用两三句说明结构、风格和比例；不要把整份内部底稿展示成用户必须逐项批准的清单。

需要保存文件时放在本次任务目录；不覆盖原图、不写入 Skill 安装目录。保留内容稿与最终绘图指令，便于复核或再次生成；临时调用可保留在工作上下文，无需为每张图创建一堆文档。

## 7. 对照材料，验收与交付

读 [检查与恢复](references/quality-and-recovery.md)，对照内容底稿与关系稿检查实际图片。检查全图、关键细节和目标阅读尺寸，不能用“生成成功”代替“检查通过”。

默认一次生成加一次针对明确问题的修正。第二次仍有关键错误，保留候选、指出问题并给出具体取舍，不标为可直接发布，也不自行无限重绘。用户另有迭代要求时跟随用户。

内容逻辑与视觉阅读分别判定，失败不能相互抵消；不以平均分掩盖一个错误数字或一条错误连接。复杂任务的交付须说明未核验项，不能把未检查记为通过。

默认回复：图片＋一行布局／插图设置／实际比例；有外部事实时补必要出处，有未解决限制时明确说明。详细提示词、内容稿和设计推导仅按需展示。无图输出明确写“分析”或“提示词”，不声称已完成生图。

文件任务另保留简短来源与覆盖记录；内容提取成功不等于理解正确，规则检查通过不等于图片通过。风格锚图与测试覆盖的实际状态见 [锚图索引](references/style-anchors.md)，不得把候选或未实测项称为已校准。
