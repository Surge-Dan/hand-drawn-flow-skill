# 材料到流程图

## 输出职责

默认把材料中的过程、机制和关系讲清楚。先确定读者问题，再选择流程、状态、交互、时间线、层级或关系图。没有过程的材料不能硬造先后与因果；也不自动转成场景插图、绘本或概念海报。

| 输入 | 提取字段 | 输出结构与边界 |
| --- | --- | --- |
| 需求/规则 | 角色、触发、动作、状态、条件、异常、终点 | 流程、泳道、状态图；保留并行与异常 |
| 设计/技术 | 模块、接口、数据、依赖、边界、约束 | 交互、数据流、结构图；包含不等于执行 |
| 书籍/文章 | 指定范围的方法、机制、命题、条件 | 方法流程或知识关系；读正文，不以目录替代论证 |
| 故事/卡片 | 人物、事件、时间证据、关系、转折 | 事件流程、时间线或人物关系；不自动分镜绘本 |
| 表格/演示 | 维度、口径、单位、有效范围 | 有依据的过程或关系；无过程则用比较/层级，不虚构趋势 |

## 内容底稿

先按[讲解策划](explanation-design.md)确定本图的读者问题。上表是提取线索，不是按文件格式分配版式；同一文档可以支持多种讲解目标。区分动作、状态、条件、全程原则、证据和输出目标，再确定哪些关系进入主图。

记录读者问题、必须事实、节点及其输入/处理/输出、关键连接及条件、旁注、允许压缩项、来源位置、覆盖缺口。简单图只需几行；复杂图保留节点与边清单。

沿“实际图片标签/对象→底稿条目→来源位置”追溯。用户明确更改原规则时记录差异。压缩不能删掉否定、条件、单位、异常或关键转折。示例数据须有用户授权或明确教学示例依据；不能为画面丰满自动添加人名、日期、参数和技术结论。

## 编排顺序

1. 写出本图应回答的问题及最易误解处，再确定入口、终点和主线；无执行顺序时确定层级或中心关系。
2. 将条件、并行、回路接到实际节点；区分执行箭头、数据流与无箭头注释引线。
3. 复杂节点内部展开，小型图形解释对象或变化；简单节点保持紧凑。
4. 提醒和限制贴近对应步骤，确有需要再设旁注栏。
5. 多角色或多回路时内部比较两种布局，选择更易追踪的一种，通常只生成一张。
6. 形成有节点对应关系的构图草案，预检容量与连接；再使用统一手绘语言及适用的[局部设计范例](visual-patterns.md)。主线不能被物体、人物、标题或装饰取代。

## 文件边界

顺序不明的故事先查时间证据；仍不明则询问或画非时序关系图。长书只覆盖实际阅读范围。抽象论点若无法支持流程，可表达关系并明确它不是执行顺序。不得为凑流程新增动作、因果或结局。

绘图指令只带本图必需事实、文字、关系、布局和保留项。原文与完整出处留在底稿；生成后检查图片而非只检查提示词。
