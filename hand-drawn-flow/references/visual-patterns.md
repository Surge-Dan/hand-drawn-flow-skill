# 局部设计范例

这些是可复用的结构配方及同题反例，不是新的画风或经用户批准的成图。箭头示意只表达关系；不能将ASCII或Mermaid直接当作已传入生图工具的视觉参考。真实图片锚点的状态见[基准记录](style-anchors.md)。

按本图难点选用一项或组合必要部分，不逐项打卡。范例中的业务事实均为说明结构的虚构材料，不能移植到用户任务。

## A. 对象变化：让读者看见处理发生了什么

**示例材料**：工单提交后等待核验，核验完整后分派；缺项时补充后重验。

|较好的组织|容易退化的组织|
|---|---|
|同一张小工单轮廓跨阶段保持标识，分别附“待核验”“完整”“已分派”；旁边动作词说明变化，缺项分支回到核验|每步换一个无关图标，只画“提交→处理→完成”，隐藏状态与条件|

```text
[工单·待核验] → 核验 ─完整→ [工单·完整] → 分派 → [工单·已分派]
                   └缺项→ 补充 → 核验
```

**视觉做法**：对象轮廓相近、状态文字不同；关键变化用少量功能色，动作与结果层级分明。图标不重复放大占满每个阶段。

**适用**：确有同一对象和状态变化。不适用纯并列观点；不要为它编造角色或状态。

## B. 局部机制：让难点获得空间

**示例材料**：输入资料经核验，再输出结果；核验内部依次检查完整性和有效期。

```text
资料 → ┌ 核验模块─────────────────┐ → 结果
       │ 完整性检查 → 有效期检查  │
       └─────────────────────────┘
```

**较好**：外部流程只有一次核验，内部展开与所属模块共用边界；输入输出端口清楚，内部占较大区域。

**反例**：上方画“核验”，下方另画同名详细流程，再用下一步箭头连接两者，让人以为核验执行两次。

**视觉做法**：细边界标所属，短标题贴边；简单前后节点紧凑，内部细节按真实次序展开。细节框不覆盖主线。

**适用**：读者需要知道内部怎样处理。不适用仅关心责任归属的任务；避免无意义剖解和多层套框。

## C. 跨角色交接：对象跨边界，责任不含糊

**示例材料**：申请人提交材料，审核员检查，完整则批准，缺项退回申请人补充并重提。

|区域|动作|跨区连接|
|---|---|---|
|申请人泳道|提交、补充、重提|提交/重提→审核员检查|
|审核员泳道|检查、批准|检查缺项→申请人补充；检查完整→批准|
|下缘通道|不放正文|承载缺项回路，起点贴检查节点，终点贴补充节点|

**较好**：角色用泳道标题识别，动作落在所属区域，跨道线标交接物或条件，返工走独立通道。

**反例**：给申请人和审核员涂不同颜色，动作仍混在一列；只写“退回”却找不到谁补、补完交给谁。

**视觉做法**：角色带轻、动作清楚，色彩不承担唯一编码。不要给每个角色都画巨大人物。

**适用**：重点在责任和交接；仅有多个角色名字不必使用泳道。重审范围从材料来。

## D. 密集说明：标签、机制、限制分层

**示例材料**：资料齐全才进入审核；审核期间保留原始材料以便追溯。

|较好|反例|
|---|---|
|主线短标签“检查资料→审核”，条件“齐全”贴所属路径；“保留原始材料”贴审核区域，标为期间要求|把整段话塞进一个小框；或画“资料齐全→保留原始材料→审核”，将约束变成动作|

**视觉做法**：主标签最先读到，条件紧跟连接，解释邻近且稍轻；不把每层都放进独立大色块。需要全程遵守的规则覆盖相关范围，不能放在容易被理解成末尾步骤的位置。

**适用**：说明或限制较多。若层级整理后仍需缩字才能容纳，回到构图和范围取舍，不继续叠旁注。

## 组合边界

一个任务可以“泳道作为整体＋某节点局部展开”，但先保证主线可追踪。为每个元素说明它解决的具体理解障碍；删掉它若不影响理解，就减少该元素的存在感。

固定的是细笔触、清晰文字和颜色职责；不固定卡片数量、坐标或背景色块。用户要求无插图时，保留有信息的状态和机制示意，去掉识别性实物插画。
